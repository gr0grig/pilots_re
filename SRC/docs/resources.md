# Файл игры и загрузка

## Общее описание

Данные игры дописаны в хвост исполняемого файла PILOTS.EXE; движок открывает собственный EXE как файл данных (пересобранный EXE без данных читает `PILOTS.EXE` рядом, см. [architecture.md](architecture.md)). Данные разбиты на ресурсы; ресурс — поток байтов-тегов, из которого загрузчик читает записи и раскладывает их в куче. Загрузка идёт целиком при старте эпизода; позже из файла читаются только фоны комнат, изображения «на диске» и фильмы.

Код: load.c (`GmRead_*`, `GmLoad_*`, `GmLzss_Unpack`, `GmImage_GetPixels`), чтение файла — `Host_Data*` в host.c.

## Хвост и индекс

`GmLoad_OpenGameFile(path)`:

1. Последние 12 байт — `GM_FILE_TRAILER`: размер индекса, версия, `formatVersion` (должна быть `GM_TRAILER_VERSION_CURRENT` = 4) и магия «=VS=».
2. Перед хвостом — заголовок индекса `GM_INDEX_HEADER`: последний номер ресурса `lastResourceId` (не больше 0xFE) и база данных ресурсов `dataBase` (не больше 80000).
3. Перед заголовком индекса — записи индекса по 5 байт: смещение ресурса (от `dataBase`) и контрольный номер, по порядку номеров.

`GmLoad_OpenResource(resourceId)` читает запись индекса, сверяет контрольный номер, переходит к началу ресурса и читает первый тег. Ресурс 1 — общий, ресурс `n + 2` — эпизод `n`.

Любая ошибка формата — `GmLoad_Fail`: файл данных закрывается, запоминается ошибка «Invalid game data file.».

## Буферизованное чтение

`GmRead_Bytes` читает через буфер `g_ReadBuf` размером `fileBufferSize` из заголовка игры (до записи заголовка буфера нет). Запросы не меньше буфера читаются из файла напрямую. `GmRead_Tell` и `GmRead_Seek` учитывают непрочитанный остаток буфера; переход сбрасывает буфер.

## Теговый поток

Теги (`GM_LOAD_TAG`), которые разбирает `GmLoad_Run`:

| Тег | Значение |
|-----|---------|
| `GMTAG_END` (0) | конец ресурса |
| `GMTAG_ARG1`, `GMTAG_ARG2`, `GMTAG_ARG3` | числовые доводы следующей записи: `index1`, `index2`, `dataOffset` |
| `GMTAG_BODY` (4) | тело записи — прочитать и применить (`GmLoad_RecordBody`) |
| `GMTAG_BLOCK` (5) | пропускаемый блок; у записи `GMREC_MOVIE` его начало запоминается в `g_MovieOffsets[slot]` |
| `GMTAG_APPLY` (0xFF) | применить запись к уже прочитанным данным `g_RecordData` (например, указать на скрипт внутри прочитанного блока по `dataOffset`) |
| прочие | заголовок записи: тип = тег & 0x7F (`GM_RECORD_TYPE`); если разряд 7 сброшен, далее числом идёт номер слота |

### Числа — `GmRead_Number`

- Тег < 0x80 — само число.
- Разряд `GMNUM_RANGED`: `n = ((тег >> 2) & 3) + 1` байт числа и два старших разряда (тег & 3) над ними; затем перенос в диапазон: при `GMNUM_NEGATIVE` — `max − число`, иначе `число + min` (таблица диапазонов для 1–3 байт, так что короткие формы не пересекаются).
- Без `GMNUM_RANGED` — `тег & 0x1F` сырых байт.

### Записи — `GmRead_Record`

Тег записи ≥ 0x80. При `GMRT_SHORT` длина (тег & 0x1F) — в самом теге. Иначе далее идут размеры по `(тег & 3) + 1` байт: хранимый и, если `тег & 0xC`, распакованный — тогда данные упакованы LZSS и распаковываются из временного буфера (`GmTempBuffer`). Размер записи — `g_RecordSize`, упакованный — `g_RecordPackedSize` (0 — без упаковки).

### Блоки — `GmRead_SkipBlock`

Тег вида `0xEC | n`, длина блока — `n + 1` байт. Блок не читается, запоминается только его начало. Так хранятся фильмы.

## LZSS — `GmLzss_Unpack(src, dst, packedSize)`

Байт флагов на 8 элементов, младший разряд первым: 1 — литерал (байт копируется), 0 — ссылка из двух байт: смещение назад = младший байт | (старшая тетрада второго байта << 8) (до 4095), длина = младшая тетрада второго байта + 3. Копирование побайтное вперёд из уже распакованного вывода (источник может перекрываться с приёмником); отдельного окна нет. LZSS используют записи ресурсов, изображения «на диске» и куски фильмов.

## Порядок загрузки — `GmLoad_Run(startEntry)`

1. Если это не первый запуск — записать автосохранение. Остановить музыку и звуки, сбросить описатели переменных и состояние изображений «на диске».
2. Разобрать общий ресурс 1: настройки по умолчанию, заголовок игры, заголовки миров, системные переменные, описатели сохраняемых переменных.
3. Разобрать ресурс эпизода `startEntry + 2`.
4. Освободить рабочий буфер комнаты. Если идёт загрузка сохранения — вернуться (комнаты восстановит `GmSaveGame_Load`).
5. Курсор — графика 0, прочитать автосохранение (`GmAutosave_Load`), войти в стартовую комнату (или в комнату 0).

Тело записи (`GmLoad_RecordBody`) читается по адресу `g_LoadPtr` и применяется `GmLoad_ApplyRecord`. Записи постоянных данных затем закрепляются в куче (`g_LoadPtr = GmHeap_Reserve(g_RecordSize)`); заголовки, начала классов, графики, звуков и записи комнат — нет (их содержимое копируется в таблицы или нужно только на время). Особые случаи:

- `GMREC_SETTINGS` читается в `g_Settings` только при первом запуске и не при загрузке сохранения;
- `GMREC_GAME_HEADER` — `GmLoad_GameHeader`: проверка версии (`GM_FILE_VERSION_CURRENT`), арена, окно и кадровый буфер, куча, таблица смещений фильмов, буфер чтения;
- `GMREC_WORLD_HEADER` применяется только для слота `startEntry` (`GmLoad_WorldHeader`: раскладка таблиц мира в куче), заголовки других эпизодов читаются вхолостую;
- первая `GMREC_ROOM` эпизода: закрепить общий буфер изображений «на диске», подготовить такт (`GmTick_InitState`), завести пул (`GmPool_Create`) и рабочий буфер комнаты; дальше записи комнат читаются в него.

## Типы записей — `GmLoad_ApplyRecord`

| Тип | Код | Применение |
|-----|-----|-----------|
| `GMREC_SETTINGS` | 0x0F | настройки по умолчанию → `g_Settings` |
| `GMREC_GAME_HEADER` | 0x10 | → `g_GameHeader` |
| `GMREC_WORLD_HEADER` | 0x11 | → `g_World` |
| `GMREC_SYSVARS` | 0x12 | `g_SysVars` указывает на запись; частота кадров из заголовка игры |
| `GMREC_ZEROED_BLOCK` | 0x13 | память отводится, адрес не запоминается |
| `GMREC_MOVIE` | 0x14 | (блок) смещение фильма → `g_MovieOffsets[slot]` |
| `GMREC_ROOM` | 0x18 | комната: смещение записи фона в файле; разряд 31 первого слова фона помечает стартовую комнату |
| `GMREC_ROOM_BUILD` | 0x19 | очистить карту, выполнить комнатное правило в абсолютном режиме (звук и музыка подавлены `g_BuildingRoom`), сохранить комнату |
| `GMREC_CLASS` | 0x20 | → `g_Classes[slot]` |
| `GMREC_CLASS_CREATE_SCRIPT`, `GMREC_CLASS_DESTROY_SCRIPT` | 0x21, 0x22 | скрипты класса (данные + `dataOffset`) |
| `GMREC_CLASS_RULES` | 0x23 | массив правил класса |
| `GMREC_RULE` | 0x2A | `rules[index1]` |
| `GMREC_RULE_PRECONDITION`, `GMREC_RULE_SCRIPT` | 0x2B, 0x2C | скрипты правила `index1` (скрипт — в слово за группами образца) |
| `GMREC_CLASS_SET_MEMBERS`, `…_CHOICES`, `…_ORIENTATIONS` | 0x38–0x3A | набор классов: битовое множество членов, список для случайного выбора, ориентации членов |
| `GMREC_GRAPHIC` | 0x40 | → `g_Graphics[slot]` (спрайт или шрифт); признак «на диске» |
| `GMREC_GRAPHIC_FRAMES`, `GMREC_GRAPHIC_DIR_FRAMES` | 0x41, 0x42 | список кадров (общий или для направления `index1`) |
| `GMREC_FRAME_IMAGE` | 0x43 | изображение кадра `index2` списка `index1` |
| `GMREC_SOUND`, `GMREC_SOUND_DATA` | 0x50, 0x51 | звук и его PCM |
| `GMREC_MUSIC` | 0x52 | дорожка → `g_MusicTracks[slot]` |
| `GMREC_PANEL_RULE`, `GMREC_PANEL_ITEMS` | 0x60, 0x61 | правило и элементы панели |
| `GMREC_VARS_KEEP_ALWAYS`, `…_KEEP_ON_RESTART`, `…_SAVEGAME_ONLY` | 0x7C–0x7E | описатели сохраняемых переменных (см. [saveload.md](saveload.md)) |

## Изображения «на диске»

У графики с `GMGR_ON_DISK` изображения кадров не остаются в памяти: после чтения записи `GMREC_FRAME_IMAGE` пиксели заменяются заглушкой `GM_IMAGE_DISK` {магия 'Disk', смещение данных в файле, упакованный размер}, а наибольший размер запоминается в `g_DiskImageMaxSize`. Под него при первой комнате закрепляется общий буфер `g_DiskImageBuffer`.

`GmImage_GetPixels(image)` возвращает пиксели обычного изображения прямо из записи, а изображение «на диске» читает из файла в общий буфер (с распаковкой, если упаковано). Кэш — одно последнее изображение (`g_DiskImageCachedOffset`).

## Фоны комнат

Запись комнаты (фон `GM_BACKGROUND` с палитрой) при загрузке только отмечается: запоминается её смещение в файле. Фон читается заново при каждом входе в комнату (`GmRoom_Enter`) в общий буфер `g_Background`.
