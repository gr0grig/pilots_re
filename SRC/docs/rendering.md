# Вывод изображения

## Общее описание

Изображение строится в 8-разрядном кадровом буфере с палитрой на 256 цветов и выводится в окно средствами GDI. Перерисовывается только то, что попало в список грязных прямоугольников. Код:

- game.c — список грязных прямоугольников (`GmDirty_Add`), сборка кадра (`GmRender_Flush`), полная перерисовка комнаты (`GmRoom_RepaintAll`);
- frame.c — кадровый буфер: копирование фона, вывод спрайтов, заливка, вывод в окно (`GmFrame_*`);
- host.c — DIB-секция, палитра, вывод в окно и растворение (`Host_InitVideo`, `Host_SetPalette`, `Host_Present`, `Host_BlitRect`);
- objects.c — пометка спрайтов грязными (`GmSprite_Invalidate`).

## Кадровый буфер

`Host_InitVideo` создаёт DIB-секцию 8 разрядов (`CreateDIBSection` берётся через `GetProcAddress` — в Win32s её может не быть) и совместимый DC. Таблица цветов DIB — индексы логической палитры 0..255 (`g_FrameBitmapInfo`, `DIB_PAL_COLORS`). Биты DIB и есть кадровый буфер; без DIB-секции буфер берётся из арены (`GmFrame_Init`).

Размер буфера — экран игры (`screenWidth × screenHeight` из заголовка). Буфер «снизу вверх»: экранная строка `y` лежит по смещению `(g_FrameHeight − 1 − y) · g_FrameStride`, поэтому переход к следующей строке — шаг назад на `g_FrameStride`.

## Грязные прямоугольники

`GmDirty_Add(left, top, right, bottom)` добавляет прямоугольник в список `g_DirtyRects` (узлы `GM_DIRTY_RECT` из кучи). Если он пересекается или соприкасается с имеющимся, тот расширяется, после чего пересекающиеся узлы сливаются, пока такие есть.

Прямоугольники добавляют:

- `GmSprite_Invalidate` — место текущего кадра спрайта: при появлении, перед сменой кадра и после неё, при перемещении, удалении, смене слоя;
- `WM_PAINT` — область обновления окна;
- реализация палитры по `WM_QUERYNEWPALETTE`/`WM_PALETTECHANGED` — вся клиентская область;
- `GmRoom_RepaintAll` — весь вид комнаты.

## Сборка кадра — `GmRender_Flush`

Вызывается в конце каждого такта (а также сразу при движении мыши, см. [ui.md](ui.md)):

1. Собрать видимые спрайты пула: записи с `GMSPR_USED | GMSPR_VISIBLE` без `GMSPR_OBJECT` (не более 1024; переполнение не проверяется).
2. Упорядочить по слою (`GM_SPRITE.layer`, байт) **по убыванию**: больший слой рисуется первым, меньший оказывается сверху.
3. Последним добавить курсор-спрайт `g_CursorSprite`, если курсор рисует движок (`!systemCursor`) и указатель в окне.
4. Для каждого грязного прямоугольника:
   - обрезать его областью вывода `[0, g_ClipWidth) × [0, g_ClipHeight)` (с учётом прокрутки `g_ScrollX/Y`, которая всегда 0);
   - скопировать в кадровый буфер фон комнаты (`GmFrame_CopyRect` из `g_Background->pixels`);
   - нарисовать все спрайты, пересекающие прямоугольник, с обрезкой — одной из четырёх функций по разрядам отражения: `GmFrame_DrawSprite`, `GmFrame_DrawSpriteMirrorX`, `GmFrame_DrawSpriteMirrorY`, `GmFrame_DrawSpriteMirrorXY`;
   - вывести прямоугольник в окно `GmFrame_Present` (с растворением, если оно запрошено);
   - освободить узел.
5. `Host_Flush` (`GdiFlush`), очистить список и признак растворения `g_DissolvePending`.

Пиксели изображения берутся через `GmImage_GetPixels`: у обычного изображения они лежат в записи, изображение «на диске» подчитывается из файла (см. [resources.md](resources.md)).

## Вывод спрайта

Спрайт рисуется кадром `GM_FRAME` (изображение `GM_IMAGE` и горячая точка `hotX`, `hotY`). Позиция:

- у спрайта, привязанного к тайлу, `x`, `y` уже пересчитаны с вычетом горячей точки (`GmSprite_UpdatePosition`, см. [animation.md](animation.md));
- у экранного спрайта (`GMSPR_SCREEN_ANCHORED` — глифы, элементы панелей, курсор) горячая точка вычитается при выводе.

Функции `GmFrame_DrawSprite*(pixels, skipX, skipY, width, height, left, top, right, bottom)`: `pixels` — изображение `width × height`, `skipX`/`skipY` (≤ 0) — сколько столбцов/строк отрезано слева/сверху, `left..bottom` — область вывода в кадровом буфере. Прозрачен только байт 0, прочие пиксели копируются как есть. Иных режимов наложения у спрайтов нет; поворотов изображения тоже нет — только отражения по осям (разряды `GMSPR_MIRROR_X`, `GMSPR_MIRROR_Y`).

Сложение пикселей с кадровым буфером (по модулю 256) есть только у кадров фильма — `GmAddBlit_*` (см. [video.md](video.md)). `GmFrame_Fill` (заливка буфера цветом) тоже используется только фильмами.

## Фон и палитра комнаты

Фон комнаты — `g_Background` (`GM_BACKGROUND`): ширина, высота, пиксели и смещение палитры `paletteOffset` (768 байт RGB внутри `pixels`). Фон читается из файла при входе в комнату.

`GmRoom_RepaintAll` ставит палитру фона и помечает грязным весь вид: `g_DissolvePending = transition`, `Host_SetPalette(палитра, 256, transition, true)`, `GmDirty_Add(0, 0, viewWidth, viewHeight)`.

`Host_SetPalette(rgb, count, gridColor, keepSystemColors)`:

1. Перед сменой палитры окно заливается чёрным (`gridColor` = 0) или расчерчивается сеткой 8×8 цветом `g_TransitionGridColors[gridColor − 1]` (чёрный, серый, светло-серый, белый). Так выглядит стиль перехода `transition` из заголовка игры.
2. Создаётся логическая палитра (`PC_NOCOLLAPSE`); при `keepSystemColors` 10 первых и 10 последних цветов берутся системные.
3. Палитра ставится в таблицу цветов DIB-секции, окну посылается `WM_QUERYNEWPALETTE`.

## Вывод в окно и растворение

`GmFrame_Present(left, top, right, bottom, dissolve)` → `Host_Present` → `Host_BlitRect`:

- при DIB-секции — `BitBlt` из её DC;
- без неё — `StretchDIBits` из буфера в том же масштабе (растяжения нет: окно всегда размером с экран игры).

С `dissolve` выводится вся клиентская область за 16 проходов: на проходе `i` — квадраты 16×16 с шагом 64 по обеим осям, начиная со смещения `(g_DissolvePatternX[i], g_DissolvePatternY[i])`, с `GdiFlush` после каждого квадрата. Растворение включается ненулевым `transition` при перерисовке комнаты, при ключевом кадре фильма и после AVI.

## Окно

Клиентская область — размер экрана игры (`Host_CreateWindow`); размер рамки считается `AdjustWindowRectEx`. Рамка изменяемая или тонкая (`GM_GAME_HEADER.resizable`); наибольший размер окна ограничен размером вида (`WM_GETMINMAXINFO`). Если окно не меньше экрана, рамка уводится за его край. `Host_ShowWindowOrIntro` отказывает с ошибкой «Game REQUIRES larger screen.», если экран меньше окна.
