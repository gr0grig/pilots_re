# Машина скриптов и правила

## Общее описание

Поведение игры задают **классы** и их **правила**. Каждый занятый тайл карты принадлежит классу; у класса с экземплярами (вид не `GMCLASS_STATIC`) на каждом такте выполняются правила. Правило сличает окрестность объекта с образцом, двигает объект, вызывает скрипт и ставит новые тайлы. Скрипты — байт-код, исполняемый `GmVm_Run`; из них вызываются встроенные функции `Native_*`.

Код: vm.c (машина), natives.c (встроенные функции и `g_NativeFunctions`), rules.c (правила, преобразования, генератор случайных чисел).

## Машина скриптов — `GmVm_Run`

`int GmVm_Run(const uint8_t *code)` выполняет байт-код с начала `code` до кода `OP_RETURN` и возвращает регистр `lo`. Скрипт выполняется целиком за один вызов: команд ожидания и передачи управления такту нет.

### Состояние

- **Аккумулятор** из двух 32-разрядных регистров: `lo` (результат) и `hi` (второй операнд). Двухместные операции считают `lo = hi op lo`, сравнения кладут в `lo` 0 или 1.
- **Стек** — отдельный массив 256 КБ, растёт вниз, адресуется побайтово. Хранит доводы встроенных функций, локальные переменные и адреса возврата подпрограмм. Вложенные запуски (встроенная функция → скрипт) продолжают стек ниже вызывающего. `GmVm_ResetStack` сбрасывает его при перезапуске такта.
- **Переменные** — две области: глобальные `g_GlobalVars` и переменные текущего объекта `g_CurVars`. Код подпрограмм тоже адресуется смещением от `g_GlobalVars`.

Операнды — 4 байта без выравнивания. Адреса передаются как `int32_t` (только x86).

### Коды команд (`GM_OPCODE`, 0x00–0x37)

| Группа | Коды | Действие |
|--------|------|----------|
| Возврат | `OP_RETURN` | конец скрипта, результат — `lo` |
| Сравнения | `OP_CMP_EQ`, `OP_CMP_NE`, `OP_CMP_LT/LE/GT/GE_SIGNED`, `…_UNSIGNED` | `lo = (hi op lo)` |
| Переходы | `OP_JZ`, `OP_JMP` | смещение от начала операнда; `OP_JZ` — при `lo == 0` |
| Стек | `OP_PUSH_LO`, `OP_POP_HI`, `OP_ADJUST_SP`, `OP_XCHG_STACK` | положить `lo`, снять в `hi`, `sp += операнд`, обмен `lo` с вершиной |
| Регистры | `OP_PUSH_IMM32`, `OP_DUP`, `OP_XCHG` | `lo = операнд` (несмотря на имя, в стек не кладёт), `hi = lo`, обмен `lo`/`hi` |
| Арифметика | `OP_ADD`, `OP_SUB`, `OP_MUL`, `OP_IDIV`, `OP_NEG`, `OP_INC`, `OP_DEC`, `OP_MUL4`, `OP_ADD4`, `OP_SUB4` | `OP_MUL` — беззнаковое 32×32, старшая половина в `hi`; `OP_IDIV` — частное в `lo`, остаток в `hi`, деление на 0 — исключение процессора |
| Биты | `OP_OR`, `OP_XOR`, `OP_AND`, `OP_SAR`, `OP_SHL` | сдвиг по модулю 32 |
| Загрузка | `OP_LOAD_SBYTE_GLOBAL/OBJECT/IND`, `OP_LOAD_DWORD_GLOBAL/OBJECT/IND` | байт — со знаком; `…_IND` — по адресу в `lo` |
| Запись | `OP_STORE_BYTE_GLOBAL/OBJECT/IND`, `OP_STORE_DWORD_GLOBAL/OBJECT/IND` | пишется `lo`; `…_IND` — по адресу в `hi` |
| Адреса | `OP_LEA_GLOBAL`, `OP_LEA_GLOBAL_ALT`, `OP_LEA_OBJECT`, `OP_LEA_LOCAL` | `lo` = адрес переменной; `…_LOCAL` — `sp + операнд` |
| Подпрограммы | `OP_CALL_SCRIPT`, `OP_CALL_INDIRECT`, `OP_RET_CALL`, `OP_RET_FREE` | вызов по смещению от `g_GlobalVars` (из операнда или из `hi`); в стек кладётся адрес операнда команды вызова, возврат пропускает 4 байта; `OP_RET_FREE` освобождает ещё и локали |
| Встроенные | `OP_CALL_NATIVE` | вызвать `g_NativeFunctions[операнд]`, результат в `lo` |

Логического «НЕ», условного перехода по ненулю и отдельного остатка от деления нет. Неизвестный код в этой реализации пропускается.

### Откуда вызываются скрипты

- предусловие и скрипт правила (`GmRule_Run`);
- скрипты создания и уничтожения класса — через `GmRunScriptWithContext`, который подставляет контекст (класс, объект, его номер и переменные, тайл, направление) и восстанавливает прежний;
- поле текста вида `GMFMT_SCRIPT_CALL` — `GmText_Print` собирает в буфере крошечную программу «вызов + возврат» (`GM_INLINE_CALL`).

## Классы и правила

`GM_CLASS`: вид (`GMCLASS_STATIC` — без экземпляров; `GMCLASS_ALL_INPUT`, `GMCLASS_POINTABLE`, `GMCLASS_FOCUSABLE` — с экземплярами, различаются вводом), маска допустимых ориентаций правил `ruleOrientations`, слой по умолчанию, размер переменных, скрипты создания и уничтожения, массив правил `rules`.

Правило `GM_RULE` — поток двойных слов:

1. заголовок `GM_RULE_HEADER`: флаги `GMRULE_PRECONDITION`, `GMRULE_PATTERN`, `GMRULE_MOVE`, `GMRULE_SCRIPT`, `GMRULE_PLACE`, `GMRULE_LAST` (последнее правило класса) и клетка хода;
2. [указатель на скрипт предусловия];
3. [группы образца];
4. [указатель на скрипт];
5. [группы размещения].

Группа — слово `GM_RULE_GROUP` (число клеток, признак последней группы, тип) и клетки `GM_RULE_CELL`: класс (или набор), флаги, смещение `dx`, `dy`. Младшая тетрада флагов — признаки сличения (`GMCELL_BY_CLASS_SET`, `GMCELL_MUST_MATCH`, режим `GMCELL_MODE_MASK`), старшая — маска направлений (`GMDIR_SOUTH`, `GMDIR_WEST`, `GMDIR_NORTH`, `GMDIR_EAST`).

### Выполнение правила — `GmRule_Run(rule, absolute)`

Обычный режим — от имени текущего объекта: координаты клеток относительны его тайла и переносятся через края карты (`GmPlaceCell_Relative`). Абсолютный режим (`absolute`) — без объекта, координаты клеток абсолютны, преобразование тождественное (`GmPlaceCell_Absolute`); так выполняются комнатные правила при постройке комнаты и правила панелей.

1. **Предусловие**: скрипт; 0 — правило не сработало.
2. **Образец**: группы клеток сличаются с картой. Клетка совпала, если класс тайла равен классу клетки (или входит в набор) и направления клетки пересекаются с направлением тайла. Клетка «срабатывает», если результат сличения равен её признаку `GMCELL_MUST_MATCH`; тогда по режиму: `GMCELL_GROUP_DONE` — к следующей группе, `GMCELL_VETO` — правило не сработало, `GMCELL_ACCEPT` — образец принят, `GMCELL_COLLECT` — запомнить смещение клетки в `g_PatternMatches` (для групп `GMPG_BY_MATCH`). Группа `GMPG_BY_MATCH`, не собравшая ни одного совпадения, проваливает правило. Если ни одна клетка не запретила правило, образец принят.
3. **Ход**: клетка хода преобразуется, маска направлений разрешается в одно (случайно, `g_ResolveDirectionMask`), затем `GmCurObject_Move` (см. [tilemap.md](tilemap.md)).
4. **Скрипт**: `GmVm_Run`. Если скрипт сменил слой объекта, его спрайт помечается грязным. Если объект двигался, а скрипт не показал новую графику, кадры спрайта выбираются заново (`GmObject_RefreshSprite`).
5. **Размещение**: группы клеток ставятся на карту (`GmTile_Place`). Тип группы: `GMPG_ONE_OF_GROUPS` — одна из 1–3 групп целиком, `GMPG_RANDOM_COUNT` — все клетки, кроме одной случайной, `GMPG_ONE_CELL` — одна случайная, `GMPG_EACH_HALF` — каждая с вероятностью 1/2, `GMPG_BY_MATCH` — клетка, совпавшая с собранным образцом.

Результат: 0 — не сработало, иначе 1 + число «самозамен» (клеток размещения с нулевым смещением).

### Ориентации

Правило задаётся для объекта, смотрящего на юг, и пробуется в разрешённых классом ориентациях. Восемь преобразований клетки `g_RuleXforms` — группа симметрий квадрата: тождественное, поворот на 90° по часовой, на 180°, на 90° против часовой и четыре отражения (`GmXform_*`). Преобразование меняет `dx`, `dy` и маску направлений (таблицы `g_XformDirMap_*`). Номер ориентации `g_CurRuleXform` складывается из разряда маски и поворота по направлению объекта (юг 0, запад 1, север 2, восток 3); отражения — номера 4–7. По нему же `GmDirIndex_MatchesRotated` поворачивает направления клавиш и пути для встроенных функций 7 и 40–41.

У набора классов могут быть ориентации членов (`GM_CLASS_SET.orientations`); тогда направление клетки берётся из ориентации члена и поворачивается по направлению клетки (`g_RotateCellByDirection`).

## Проход правил — `GmRules_RunTick`

Обходит пул от вершины (или от отложенного объекта `g_ResumeObject`):

- свободные видимые спрайты без владельца доигрывают анимацию (если нет фильтра классов);
- экземпляры классов вне фильтра `g_ActiveClassFilter` пропускаются;
- экземпляр с `GMUT_SKIP_TICK` (создан в этом такте впереди обхода) пропускается один раз;
- у двигающегося экземпляра (`GMOBJ_MOVED`) доигрывается анимация хода; пока она не кончилась, правила не выполняются;
- иначе ставится контекст (`g_CurObject`, `g_CurClass`, `g_CurVars` — поле `vars` или блок в куче) и выполняются правила класса по порядку; первое сработавшее заканчивает обработку объекта, если не было `Native_ContinueRules`.

Если `Native_ContinueRules` вызван на последнем правиле, объект становится `g_ResumeObject`: проход прерывается, а следующий такт начнётся с этого объекта и на нём же закончится. Объект, заменивший сам себя, передаёт фокус дальше (`GmFocus_Advance`).

`Native_SetClassFilter` заставляет `GmGame_Tick` повторять проход, пока фильтр не снят.

## Случайные числа

Линейный конгруэнтный генератор ANSI C: `g_RandomSeed = g_RandomSeed · 1103515245 + 12345`; число в `[0, n)` — `(n · (g_RandomSeed >> 16)) >> 16`, затем генератор продвигается. Засевается временем в `GmGame_Init`, `GmRoom_ResetView` и `GmTick_InitState`. Используется для выбора направлений, членов наборов классов, групп размещения и в `Native_Random`; к анимации отношения не имеет.
