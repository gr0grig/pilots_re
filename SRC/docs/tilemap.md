# Тайловая карта и поиск пути

## Общее описание

Мир комнаты — сетка тайлов `g_World.mapWidth × g_World.mapHeight`. Каждый тайл занят классом или пуст; экземпляры классов стоят на тайлах и ходят по ним только через правила и встроенные функции — своей «физики» нет. Поиск пути — волна по отдельной карте проходимости.

Код: objects.c (постановка и очистка тайлов, ход), rules.c (сличение и размещение по правилам), path.c (`GmWalkMap_*`, `GmPath_*`), natives.c (встроенные функции 10–12, 27–29, 35–45).

## Карта тайлов

`g_TileMap` — массив `GM_TILE` (2 байта): номер класса и флаги. Старшая тетрада флагов — направление тайла (`GMDIR_SOUTH`, `GMDIR_WEST`, `GMDIR_NORTH`, `GMDIR_EAST`). Пустой тайл — класс `GMCLASS_EMPTY_TILE` (0xFE); слово `GMTILE_EMPTY_RAW` (0xF0FE) — пустой тайл со всеми направлениями. Класс `GMCLASS_ANY` (0xFF) — «любой» в поиске пути.

Длина строки — степень двойки не меньше ширины (`g_TileMapShift` по таблице `g_MapRowShifts`, от 4 до 256 клеток); тайл `(x, y)` — `g_TileMap[x + (y << g_TileMapShift)]`. Координаты тайлов хранятся в байтах (`GM_TILEPOS`), так что карта не больше 256×256. Размер тайла в пикселях — `g_GameHeader.tileWidth × tileHeight`.

Относительные координаты (клетки правил, ход) переносятся через края карты по модулю её размеров — карта замкнута.

Карта общая для всех комнат эпизода; при смене комнаты её содержимое сохраняется и восстанавливается (`GmRoom_SaveState`, `GmRoom_Enter`).

## Экземпляры на карте

Тайл экземпляра содержит класс объекта и его направление. То, что лежало на тайле до прихода объекта, хранится в объекте — `GM_OBJECT.underTile` (у объекта в младших разрядах его флагов ещё признаки `GMUT_SKIP_TICK` и `GMUT_HAS_TEXT`).

`GM_OBJECT`: флаги (`GMOBJ_USED`, `GMOBJ_INSTANCE`, `GMOBJ_MOVED`, `GMOBJ_VARS_ALLOCATED`, направление в старшей тетраде), класс, `underTile`, разряды ввода, слой, тайл, спрайты покоя и показа, переменные (до 4 байт — прямо в поле `vars`, длиннее — блок кучи).

### Постановка — `GmTile_Place(cell, tileX, tileY)`

1. Клетка с `GMCELL_BY_CLASS_SET` — берётся случайный член набора; если у набора есть ориентации, направление — ориентация члена, повёрнутая по направлению клетки.
2. Класс `GMCLASS_EMPTY_TILE` — тайл очищается вместе со свободными спрайтами, и всё.
3. Маска направлений клетки разрешается в одно (случайно).
4. Класс с экземплярами: тайл очищается, заводится экземпляр (`underTile` — прежний тайл); экземпляр, созданный впереди идущего обхода пула, пропускает текущий такт (`GMUT_SKIP_TICK`); первый фокусируемый получает фокус. Статический класс: тайл очищается вместе со свободными спрайтами.
5. На карту пишется класс и направление, выполняется скрипт создания класса.

### Очистка — `GmTile_Clear(tileX, tileY, alsoFreeSprites)`

Экземпляр на тайле разбирается: удаляются его спрайты, блок переменных, текст и запись пула, фокус переходит дальше; на карту возвращается тайл, лежавший под объектом. С `alsoFreeSprites` удаляются и свободные спрайты, начатые на тайле. Затем выполняется скрипт уничтожения класса, стоявшего на тайле.

### Ход — `GmCurObject_Move(step)`

Ненулевое смещение `(dx, dy)`: объект уходит с тайла правила (там восстанавливается его `underTile`), целевой тайл очищается и запоминается в `underTile`, на карту пишется класс и направление объекта. Смена направления разворачивает объект и его тайл. При любом изменении поднимается `g_CurObjectMoved`, после чего правило обновит спрайт (см. [animation.md](animation.md)).

### Тайл под объектом

- `GmCurObject_SetUnderTile(classOrSet, fromClassSet)` — поставить под объект статический тайл (класс или случайный член набора, направление юг) и выполнить скрипт создания класса; встроенные функции 28, 29.
- `GmCurObject_DestroyUnderTile()` — удалить свободный спрайт этого тайла, выполнить скрипт уничтожения и пометить `underTile` пустым; встроенная функция 27.
- Проверки: `Native_IsUnderTileEmpty`, `Native_UnderTileIs`, `Native_UnderTileInSet`.

## Направления

- `GM_DIRECTION` — разряды маски: юг 0x10, запад 0x20, север 0x40, восток 0x80. Ими пользуются тайлы, клетки правил и объекты; маска с несколькими разрядами разрешается в одно направление случайно (`g_ResolveDirectionMask`).
- `GM_DIR8` — номер направления 0..7 по часовой: С, СВ, В, ЮВ, Ю, ЮЗ, З, СЗ. Им пользуются клавиши направлений и результаты поиска пути. `GmDirIndex_MatchesRotated` поворачивает номер по ориентации текущего правила.

## Карта проходимости

`g_WalkMap` — байт на тайл, строки длиной `mapWidth` (без выравнивания до степени двойки). Метки `GM_WALK_CELL`: `GMWALK_OPEN` (0) — свободно, `GMWALK_GOAL` (2) — цель, `GMWALK_BLOCKED` (3) — непроходимо, `GMWALK_MARK4/5/6` — фронты волны. Края карты проходимости не переносятся.

Карта строится заново перед каждым поиском одной из функций:

| Функция | Свободно | Цель | Поиск |
|---------|----------|------|-------|
| `GmWalkMap_GoalsClassNoObstacles(classIndex)` | всё прочее | тайлы класса | только направление |
| `GmWalkMap_GoalsClassEmptyFree(classIndex)` | пустые | тайлы класса | путь |
| `GmWalkMap_EmptyFree()` | пустые | тайл цели пути | путь |
| `GmWalkMap_ClassFree(classIndex)` | тайлы класса | тайл цели пути | путь |
| `GmWalkMap_GoalsInSetNoObstacles(memberBits)` | всё прочее | классы набора | только направление |
| `GmWalkMap_GoalsInSetEmptyFree(memberBits)` | пустые | классы набора | путь |
| `GmWalkMap_SetFree(memberBits)` | классы набора | тайл цели пути | путь |

## Поиск пути

### Подготовка

`GmPath_Setup(target)`: цель — тайл щелчка (`g_ClickTileX/Y`) для событий действия или тайл под указателем (`g_PointerTileX/Y`); начало — тайл текущего объекта; направления `g_PathDir4`, `g_PathDir8` = −1, `g_PathFound` = false.

### Прямое направление — `GmPath_DirectDirection`

Без карты, по разности координат. Если разности соизмеримы (каждая меньше учетверённой другой) — диагональ в `g_PathDir8` и большая ось в `g_PathDir4`; иначе направление по главной оси, причём в `g_PathDir8` оно пишется, только если по этой оси не меньше двух шагов. Цель на месте объекта — путь не найден.

### Волна — `GmPath_Search(directionOnly)`

Поиск в ширину по четырём соседям: клетка объекта получает метку 6, затем фронты расходятся шагами 6→4, 4→5, 5→6 (`GmPath_ExpandWave4From6`, `GmPath_ExpandWave5From4`, `GmPath_ExpandWave6From5`), пока волна не коснётся клетки-цели или не иссякнет. Три чередующиеся метки позволяют отличать соседние фронты без счётчика расстояния. Достигнутая клетка-цель становится целью пути.

Затем либо прямое направление к найденной цели (`directionOnly`), либо `GmPath_Trace`: путь прослеживается от цели к объекту по убывающим фронтам, на каждом шаге предпочитается ось с большим расстоянием до объекта. Результат: `g_PathDir4` — первый шаг (по стороне), `g_PathDir8` — направление на клетку через одну (диагональ), если путь длиннее одного шага.

### Поиск по классу — `GmPath_SeekClass(target, classIndex, mode)`

- `target` = `GMEV_ACTION1`/`GMEV_ACTION2`: нужен запомненный щелчок тем же действием по тайлу этого класса (или `GMCLASS_ANY`);
- `target` = `GMEV_NONE`: класс тайла под указателем должен совпасть;
- иначе (`GMEV_NO_TARGET`) — к ближайшему тайлу класса: только направление (`GMSEEK_DIRECTION_ONLY`) или путь в обход занятых.

Для первых двух случаев `mode`: `GMSEEK_DIRECTION_ONLY` — прямое направление, `GMSEEK_THROUGH_EMPTY` — путь по пустым тайлам, иначе — путь только по тайлам класса. `GmPath_SeekClassSet` — то же для набора классов.

### Встроенные функции

| № | Функция | Действие |
|---|---------|----------|
| 35 | `Native_SeekPointer(mode)` | `mode` 3–5 — к тайлу под указателем, 6–8 — к щелчку действием 1, 9–11 — действием 2; в тройке: прямо, прямо если тайл пуст, путь по пустым |
| 36 | `Native_SeekClass(classIndex, mode)` | `mode` 1/2 — к ближайшему тайлу класса (прямо / путь); 3–11 — те же тройки целей, но цель должна быть тайлом класса; в тройке: прямо, путь по пустым, путь только по тайлам класса |
| 37 | `Native_SeekClassSet(classSet, mode)` | то же для набора классов |
| 38–41 | `Native_PathDir4Is`, `Native_PathDir8Is`, `…Rotated` | путь найден и направление равно заданному (с поворотом по правилу) |
| 42 | `Native_PathAction(action)` | `GMPATH_FORGET` — забыть путь и щелчок, `GMPATH_CLEAR_GOAL` — очистить тайл цели, `GMPATH_MOVE_TO_GOAL` — переставить объект на цель |
| 43, 44 | `Native_PlaceAtGoal(classIndex)`, `Native_PlaceAtGoalFromSet(classSet)` | поставить класс на тайл цели |

Коды `mode` — `GM_SEEK_COMMAND`. Признак `g_PathFound` сбрасывается перед правилами каждого объекта, так что найденный путь действует только в правилах того объекта, который его искал.
